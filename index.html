A different starting point

不是另一个聊天窗口，
而是一条可执行的工作流。

你只需要说清目标。Agent 会决定读取哪些文件、调用什么工具、何时请求许可， 再把你配置的验证命令跑完；CLI 与 Web 展示的是同一条真实执行链。

任务可以暂停、审阅、回退和恢复。会话不是一次性的回答，而是保存在本机、 可以继续追踪的工程记录。

Capabilities

从一条任务，到可核对的交付。

执行、上下文、模型、恢复和扩展都在同一套 Agent Core 内完成。你可以换入口，但不需要重新解释项目，也不会得到两套互相冲突的会话。

01 / EXECUTION

真正的工具循环

搜索、读取、编辑、命令和多模态输入组成连续循环。只读工具可并行，写操作保持顺序和授权。

  • read_file
  • edit_file
  • run_command
02 / CONTEXT

理解项目的运行规则

自动加载工作区规则和项目上下文。修改代码后，可以把 pnpm check 一类命令设为完成门槛，没有成功退出码就不能宣称完成。

AGENTS.md context / frozen
03 / MEMORY

会积累，但不会擅自决定

长期记忆与可复用 Skill 都从真实轨迹中形成。候选内容经过审核后才影响后续会话。

USER.md MEMORY.md SKILL.md
04 / RECOVERY

会话不在刷新后消失

消息、事件、审批、任务进度和检查点写入 SQLite。刷新页面、换客户端或进程中断后， 仍能按事件序号回放并判断哪些动作已经发生。

05 / EXTENSIBILITY

给模型更多工具，不把上下文一次占满。

MCP、LSP、Skill 与后台调查工具按需发现。长命令、独立子 Agent 和大工具输出各有持久化边界，父会话只接收必要摘要与可回查引用。

MCP LSP SKILL SUBAGENT agent
06 / SCENES

同一 Agent，按任务切换工作方法。

Coding 区分小修与复杂多角色流程，Blog 可选择调研后撰稿审稿，Brainstorm 固定生成多个方向再质疑和收敛。场景只改变工作流，不会扩大工具、网络或权限边界。

  • /scene coding run …
  • /team
  • /workflow
The loop

每一步都留下证据。

01

Bind

绑定工作区

选择一个本地项目。文件访问、命令目录和项目记忆都被限制在这个边界内。

02

Delegate

描述要完成的事

从 CLI 或 Web 发起任务。模型读取真实文件，形成任务进度，并在需要时请求许可。

03

Prove

审阅结果，而不是猜测

检查工具结果、修改摘要与验证退出码。失败就停在失败处，不把不确定包装成完成。

prompt context tools approval verified

CLI / TERMINAL

在项目目录里直接开始

Fast path

适合快速定位代码、连续修改、运行测试，以及用脚本发起单次任务。

  1. 01
    安装并进入项目 
    npm install -g clawsmith
cd ~/projects/my-app
clawsmith

    在项目根目录启动，当前目录会自动成为 Agent 的工作区。

  2. 02
    连接模型服务 
    /model status
/model configure openai
/model default openai/gpt-4o-mini

    也可以直接启动离线 Demo。真实任务需要 OpenAI-compatible Provider。

  3. 03
    描述结果，而不是步骤

    “先阅读项目，定位登录超时。修复后补充回归测试，并运行 pnpm check。”

    默认模式下只读分析会直接执行；写文件和变更命令会暂停等待你的审批。 输入 y 允许本次动作，输入其他内容拒绝。

  4. 04
    审阅结果、回退或退出 
    /undo list
/undo <turn-id>
/exit

    检查工具结果和验证退出码。文件被外部修改时，整批回退会停止，而不是覆盖你的内容。

WEB / WORKBENCH

把执行过程摊开来看

Visual path

适合第一次使用、审阅 diff、处理审批、观察长任务，以及从另一台设备只读查看。

  1. 01
    启动本地 Web 面板 
    clawsmith web
# http://127.0.0.1:3210

    默认只监听 loopback，不向局域网暴露端口。

  2. 02
    添加工作区

    点击左侧工作区旁的 +，选择本地项目目录。工作区决定文件访问、 命令目录和项目记忆的边界。

  3. 03
    配置全局模型

    打开“设置 → 模型”，填写 Provider、Base URL、模型列表和 API Key。保存后把可用 Provider 设为默认。Key 只会显示“已配置”，不会回显。

  4. 04
    发起任务并处理审批

    点击“新建对话”，输入目标并发送。会话标题会在首条消息后生成； 写操作出现时，在审批卡中核对路径和命令，再选择允许一次或拒绝。

  5. 05
    检查 diff、任务与用量

    工具卡显示真实执行结果，回答下方显示本轮 token。会话底部可查看检查点、 修改 diff 和待恢复动作；输入 / 打开 Web 命令列表。

ONE SESSION
Terminal 里开始，Web 里继续看。

CLI 和 Web 不复制对话。消息、工具事件、审批、命令任务和检查点都落在同一个 ~/.clawsmith/sessions.sqlite；不同进程通过租约保证同一会话只有一个写入者。

events → replay → recover
Advanced playbook

日常进阶用法。

这些用法建立在基础流程之上。建议先用 plan 模式观察 Agent 的判断，再逐步扩大自动化范围。

AUTOMATION

把只读分析接进脚本

一次性执行不打开交互面板。默认没有审批者，需要审批的动作会被拒绝； 用 plan 做只读自动化最安全。 

clawsmith --permission-mode plan \
  --prompt "分析测试失败，给出最小修复方案" \
  --result-json ./agent-result.json

交互式写任务不要直接加 allow-all。确需无人值守写入时，必须在受信任、 可恢复的隔离工作区中显式使用 --permission-mode allow-all --yes。

MODEL + MODE

模型与权限分开控制

模型选择决定“谁来推理”，权限模式决定“动作能走多远”。切换模型不会自动扩大权限。 auto 会在输出前按任务复杂度、上下文、工具/图片能力和成本选择候选； 健康检查失败或瞬时错误只会切换尚未产生输出的请求。 

# CLI
clawsmith --permission-mode plan
/model switch

# Web 输入框
/permissions allow-all

Web 在输入框权限选择器中切换会话模式；持久 allow/ask/deny 规则位于“设置 → 权限”。

LONG TASKS

让构建和开发服务器继续运行

对 Agent 说“启动开发服务器并等待我继续操作”。长任务会获得独立 task ID， 不受当前回答结束影响。 

/commands
/commands log <task-id>
/commands input <task-id>
/commands cancel <task-id>

Web 在“设置 → 长任务”查看输出、标准输入、PTY 尺寸与停止操作。

RECOVERY

失败时先确认副作用，再恢复

模型或审批失败可以从持久检查点继续；命令、网络等未知副作用必须先检查现场， 再显式确认。 

/resume-turn
/resume-turn confirm
/requests
/diagnostics

Web 的“停止”只取消当前流。未知副作用仍会保守记录为失败，不会自动重放工具。

MEMORY + SKILLS

把重复经验变成可审核资产

长期记忆和 Skill 都先形成候选，审核后才进入后续会话。它们不会直接修改权限规则。 

/memory remember 项目约定 :: 使用 pnpm 验证
/memory search 发布流程
/skills pending
/skills approve <id>

Web 在“设置 → 记忆 / 技能”审核、拒绝或归档。

SCENES + WORKFLOWS

让多角色流程可恢复、可审计

选择场景后可以直接运行专属 DAG。实现、测试、评审角色分别在隔离 worktree 中工作；测试角色只能改测试目录并运行允许的测试命令，前序 patch 以 artifact 传给后续角色。 

/scene coding
/scene run 为解析器补齐错误分支和测试
/team
/workflow show <run-id>
/workflow journal <run-id>

测试失败或评审 BLOCK 会带上 blockers 和 patch 进入有上限的返工。Workflow Run 与 journal 原子写入 SQLite；进程中断后已经开始的写步骤标记为 unknown，不会自动重放。 Web 在“设置 → 团队任务 / 工作流”查看阶段、负责人、产物和恢复控制。

PROTOCOL + SDK

从任意 sequence 重连，不复制状态推导

协议 v21 提供版本协商、能力清单、公共事件 Schema 和必须理解 / 可忽略事件分类。 TypeScript SDK 统一处理 SSE、去重、审批、取消和 artifact 读取，旧 v20 客户端仍在 兼容窗口内。 

import { ClawsmithClient } from 'clawsmith/sdk'

const client = new ClawsmithClient({ baseUrl: 'http://127.0.0.1:3210' })
const capabilities = await client.capabilities()
const session = await client.createSession({ title: 'SDK task' })

for await (const event of client.submitTurn(session.sessionId, task)) {
  lastSequence = event.sequence
}

服务端对不兼容客户端返回 426，不静默降级。消息、工具、权限、取消、artifact 和错误 都有版本化 JSON Schema；同一主版本只允许可选字段和可忽略事件扩展。

REMOTE + DEVICES

从另一台设备查看，而不是直接暴露本地端口

默认 Web 只在本机可用。需要远程访问时，使用至少 32 字符的 owner token，并在 TLS 终止代理后运行；不要直接把明文 HTTP 端口暴露到公网。 

export CLAWSMITH_API_TOKEN="$(openssl rand -hex 32)"
HOST=0.0.0.0 CLAWSMITH_ALLOW_REMOTE=1 clawsmith web

登录后进入“设置 → 设备”配对 operator 或 viewer。viewer 只能读取被授权的 workspace，撤销设备后它的 Cookie 和 Bearer 立即失效。

Permission by design

能力越大，
边界越要具体。

审批不是最后一道装饰。路径限制、危险命令拦截、沙箱和审计在批准之后仍然生效。

系统边界不会被 allow-all 关闭。

permission mode mutation policy
default 变更前逐次询问 ASK
plan 只读分析与规划 READ
accept-edits 自动接受工作区编辑 EDIT
unattended 无法确认时直接拒绝 DENY
allow-all 二次确认后放行常规操作 OPEN

allow-all 也不会关闭显式 deny、灾难命令拦截、路径边界和命令沙箱。

Questions

开始之前，
你可能想知道。

我的代码会上传到 clawsmith 的服务器吗？

会话、记忆、Skill 和权限数据默认保存在本机。模型请求会发送到你配置的模型服务， 因此请选择符合个人或团队数据要求的 Provider。clawsmith 不会额外搭建一个中转云服务。

必须配置 API Key 才能体验吗？

不需要。clawsmith 默认使用离线 Demo，不会主动发起模型请求。 执行真实任务时再配置 OpenAI-compatible Provider。

Agent 可以直接执行任何命令吗？

不可以。写操作和高风险命令会根据权限模式请求审批；灾难命令会被硬拒绝； 命令还受超时、CPU、文件大小、输出和平台沙箱限制。

CLI 和 Web 是两套不同的会话吗？

不是。它们共享同一套 Agent Core、SQLite 会话、事件、权限和任务状态。 两个进程可以观察同一会话；同一时刻只有一个 turn 能取得执行租约。

支持哪些操作系统？

macOS、Linux 和 Windows 都支持 CLI、Web 与工作区文件操作。macOS 和 Linux 提供原生命令沙箱；Windows 默认使用实验性的 windows-acl 写入/删除部分隔离，读取和网络仍未隔离。需要严格边界时应显式配置 Docker。

当前是开源软件吗？

当前版本是专有软件。npm 分发包允许按许可证安装和运行；复制、再分发、商业托管或二次开发前， 请先阅读仓库中的许可证。
