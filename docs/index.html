    01 / OVERVIEW

    clawsmith 是什么

    clawsmith 是本机运行的 Agent Harness。它把一次任务拆成 模型请求 → 工具调用 → 权限裁决 → 会话事件 → 验证证据 → 交付结果， 并将所有可见状态持久化。CLI、Web、HTTP API 和 SDK 消费同一套 Agent Core， 不会各自实现一套会话或审批状态机。

    一套核心，多种入口

    层级职责可替换点
    Agent Core模型循环、工具批处理、上下文压缩、事件与恢复Provider、Tool、Context Provider
    RuntimeProfile、Session、权限、Skill、Memory、MCP、LSP、SandboxStore、Sandbox、Execution World
    SurfacesCLI、Web、HTTP/SSE、SDK、GatewayWeb Slot、Gateway Adapter
    AutomationCron、Workflow、Subagent、Worktree、Task GraphAgent manifest、Workflow definition

    本地优先不等于完全离线

    LOCAL DATA

    会话、审批、记忆和凭据默认保存在本机，但真实模型请求会发送到你配置的 Provider。 clawsmith 不会把“本地优先”解释成“完全离线”。

    02 / QUICKSTART

    5 分钟运行第一条任务

    1. 安装使用 npm、pnpm 或 npx。Node.js 版本必须为 22.13 或更高。
    2. 选择入口CLI 适合同步编码；Web 适合审批、轨迹和可视化 diff。
    3. 配置 ProviderWeb 的“设置 → 模型”可添加任意 OpenAI-compatible Provider。
    4. 提交可验证任务给出目标、约束和验证命令，例如“修复失败测试并运行 pnpm test”。
    npm install -g clawsmith
clawsmith --version
clawsmith
    pnpm add -g clawsmith

    npx clawsmith@latest
npx clawsmith@latest web

    启动 Web 工作台

    clawsmith web
# http://127.0.0.1:3210

    发起可验证任务

    cd ./your-project
clawsmith --prompt "修复登录超时；先定位调用链，修改后运行 pnpm check，并报告证据"

    使用 Web 完成审批与复核

    打开 http://127.0.0.1:3210，添加工作区后进入“设置 → 模型”配置 Provider。Web 会展示模型轨迹、工具日志、diff、审批、artifact 和请求证据， 适合需要逐步审阅的任务。

    SUCCESS SIGNAL

    任务完成的标志不是模型说“完成”，而是产生了成功的命令工具结果、最终 diff、 artifact 或 goal evidence。工作区写入后，配置了 verificationCommand 的项目必须完成验证。

    04 / FIRST TASK

    写一个 Agent 能可靠完成的任务

    任务描述四要素

    1. 目标：要改变什么行为，而不是只说“看看项目”。
    2. 约束：不能修改哪些目录、必须保留哪些 API、允许哪些依赖。
    3. 验收：需要运行哪个测试、构建或浏览器场景。
    4. 证据：要求报告命令退出码、diff、截图或 artifact。
    修复 refresh token 过期后登录无限重试的问题。
约束：只修改 packages/auth 和对应测试；不要升级依赖。
验收：pnpm test -- auth 与 pnpm typecheck 必须通过。
完成后报告修改文件、测试退出码和仍存在的风险。

    配置项目验证命令

    {
  "verificationCommand": "pnpm check"
}

    文件位于 .clawsmith/project.json。一旦 Agent 修改工作区文件， Core 会要求后续回合取得该命令的成功证据，否则不能把任务标记完成。

    从简单任务逐步升级

    第一条任务建议限定在两个文件以内的修复。确认 Provider、审批和验证链路正常后， 再使用 Plan、Subagent、Worktree 和 Workflow 处理跨模块任务。

    05 / ARCHITECTURE

    Agent 如何执行

    每次 turn 先获取 Session lease，再构造项目上下文和模型请求。模型只能看到当前 Capability composition 允许的工具；每个工具调用依次经过 schema 校验、Hook、 权限服务、沙箱/Execution World、超时和取消、结构化结果与 checkpoint。

    组合视图

    CLIWebHTTPSDKGateway
    同一 Session / Event / Approval 事实源
    REQUESTContext Builder

    AGENTS.md · Skill · Memory · 附件

    LOOPAgent Core

    Model → Tool → Result → Model

    CONTROLPolicy Plane

    权限 · Hook · Sandbox · Budget

    SQLiteArtifactAttachmentEvent JournalCheckpoint

    关键不变量

    • 模型请求 schema 在构造阶段冻结，运行时插件更新只在下一轮生效。
    • 副作用工具不会因为断线或进程恢复而自动重放；结果未知时要求人工确认。
    • CLI、Web、Cron 和 Gateway 任务共享同一 Session、lease、审批和 artifact 规则。
    • Execution World 可组合 local、Docker、SSH 或插件 Provider； 文件、命令、PTY、取消和 checkpoint 使用同一执行契约。

    持久事实源

    Session、event、message、tool result、approval、todo、goal、plan、queue、 checkpoint 和 artifact 都有持久事实源。刷新页面或切换客户端只重新读取事实， 不从浏览器状态推断 Agent 是否执行完成。

    06 / CLI

    CLI 编程工作流

    交互式启动进入 REPL；--prompt 用于脚本和 CI。斜杠命令管理 Provider、 会话、计划、后台命令、Worktree、Cron、记忆和导出。

    交互、脚本与本地服务

    clawsmith
clawsmith --prompt "run the tests and fix the first failure"
clawsmith --status
clawsmith serve
PORT=3210 clawsmith web

    高频斜杠命令

    命令用途
    /plan创建、审批、拒绝和验证计划
    /commands查看后台命令、日志、输入、resize 和取消
    /requests查看模型请求证据与脱敏 request snapshot
    /worktree创建、切换、比较、应用和清理隔离方案
    /scene切换 general、coding、blog、brainstorm 场景
    /cron创建和维护持久定时任务
    /memory /skills审核长期记忆与 Skill 候选

    推荐的 CLI 使用节奏

    小修先用 --prompt 或单轮 REPL；跨模块任务先使用 /plan， 长测试使用后台命令，失败后先查看 /requests 和 /commands， 再决定修复或恢复，不要重复提交同一任务。

    07 / WEB

    Web 工作台与多客户端

    Web 不是演示壳。它和执行层共享同一会话事件源，提供工具轨迹、diff、审批、 请求证据、附件预览、Worktree 比较、Cron、Gateway、插件管理和安全事件。

    启动与远程访问

    # 本机默认
clawsmith web

# 远程访问：必须提供至少 32 字符 token
export CLAWSMITH_API_TOKEN="$(openssl rand -hex 32)"
HOST=0.0.0.0 CLAWSMITH_ALLOW_REMOTE=1 clawsmith web

    多客户端工作方式

    • 运行中的 turn 支持排队、暂停、编辑、重排和 interrupt-and-redirect。
    • 审批、设备和权限规则支持多客户端同步；viewer 设备保持只读。
    • Web client 插件可扩展 settings section、tool result、composer 和 sidebar slot。
    • Editor bridge/ACP 可把 VS Code、JetBrains、Zed 或自定义编辑器连接到同一会话。

    Web 中的主要检查面

    区域开发者用途
    轨迹查看模型请求、工具参数、结果、耗时和失败分类
    审批允许/拒绝命令或写入，并查看规则来源
    Diff / Checkpoint审阅文件变化、回退 turn 或文件
    设置Provider、MCP、权限、Memory、Cron、Profile、插件和 Worktree

    工具如何被激活

    核心文件、搜索、命令和交互工具直接可见；MCP、浏览器诊断、Worktree、Task Graph、 Workflow、媒体和插件工具通常标记为 deferred。模型先调用 search_tools，Core 记录本会话发现过的 schema，并在下一轮模型请求中激活。

    工具调用示例

    read_file(path="src/auth.ts", startLine=40, endLine=120)
search_files(query="refreshToken\\(", path="src", regex=true, contextLines=2)
run_command(command="pnpm test -- auth", cwd="packages/api")
apply_patch(files=[...])
submit_review(scope={kind:"session"}, findings=[...])
prepare_delivery(commitMessage="fix: refresh auth token")
    09 / CODE TOOLS

    代码、文件与搜索工具

    读取大文件时使用行窗口

    read_file(
  path="src/auth/session.ts",
  startLine=80,
  endLine=180,
  maxBytes=30000
)

    read_file 仅接受工作区内普通 UTF-8 文件。行窗口返回明确行号， 避免大文件只读取前 100KB。

    搜索优先于全目录读取

    search_files(
  query="refreshToken\\(|accessToken\\(",
  path="packages",
  regex=true,
  caseSensitive=false,
  contextLines=3,
  fileType="ts"
)

    先用 search_files 缩小范围，再用 read_file 读取命中位置； 只有需要完整结构时才使用 code_symbols 或 LSP。

    精确编辑与多文件补丁

    {
  "files": [
    {
      "path": "packages/auth/session.ts",
      "replacements": [
        { "oldText": "retry = 3", "newText": "retry = 1" }
      ]
    },
    {
      "path": "packages/auth/session.test.ts",
      "replacements": [
        { "oldText": "expect(retries).toBe(3)", "newText": "expect(retries).toBe(1)" }
      ]
    }
  ]
}

    edit_file 要求唯一匹配；确需批量替换时显式设置 replaceAll=true。apply_patch 会先校验所有文件， 再开始写入。

    Notebook、图片与生成文件

    • notebook_edit 按 cell id 或索引修改 Jupyter，不重写无关单元。
    • read_image 把工作区图片注册为当前会话附件。
    • present 把报告、截图或生成文件交给当前客户端。
    10 / EXECUTION

    命令与执行工具

    短命令使用 run_command

    run_command(
  command="pnpm test -- auth",
  cwd="packages/api",
  timeoutMs=120000
)

    cwd 必须是 workspace 内真实目录；不得通过路径参数绕过 workspace 边界的路径。 非零退出码仍作为工具成功返回，模型必须读取 stderr 和 exit code。

    长任务使用 start_command

    start_command(command="pnpm dev", cwd="apps/web")
command_output(taskId="command-…", wait=true, waitTimeoutMs=300000)
command_status(taskId="command-…")
cancel_command(taskId="command-…")

    等待不会取消任务；超时只停止本次等待。需要交互程序时启用 PTY， 再使用 command_input 和 resize_command_pty。

    执行边界

    • 命令经过平台沙箱、资源限制和危险命令硬拒绝。
    • 后台任务不绑定单轮 turn，宿主退出后转为 orphaned，不会自动重放。
    • 项目感知使用 project_info，不要反复猜测 Node、包管理器或脚本入口。

    12 / DELIVERY

    验证、Review 与交付

    标准交付顺序

    1. 读取项目规则并修改代码。
    2. 运行项目验证命令并取得 exit code。
    3. 提交结构化 review，每个 finding 必须绑定 changed path。
    4. 生成 side-effect-free delivery preview。
    5. 用户批准后 commit；只有明确要求才 push 或创建 PR。
    6. 通过 delivery_status 查询 CI。

    Review 示例

    submit_review(
  scope={kind:"session"},
  findings=[
    {
      severity:"warning",
      title:"Refresh race remains",
      summary:"Two tabs may still refresh concurrently.",
      evidence:"No test covers simultaneous refresh.",
      path:"packages/auth/session.ts",
      line:84
    }
  ]
)

    交付工具

    工具作用副作用
    submit_review绑定 diff 哈希和 findings无
    prepare_delivery预览 branch、commit message 和 diff无
    deliver_changescommit、可选 push/PR需审批
    delivery_status读取 CI 状态只读
    13 / POLICY

    权限、审批与沙箱

    选择权限模式

    模式行为典型场景
    default只读自动，变更审批日常交互
    plan只允许分析方案设计
    accept-edits工作区编辑自动，其他仍审批可信重构
    unattended需要交互的动作直接拒绝Cron、后台 Agent
    allow-all跳过常规审批，二次确认受控自动化

    用持久规则减少重复审批

    权限规则可按 user、project、session 作用域组合 tool、pathPrefix 和 commandPrefix。 即使 allow-all 也不会关闭 deny 规则、Hook、工作区路径边界、灾难命令拦截、 资源限制和平台沙箱。 

    {
  "scope": "project",
  "behavior": "ask",
  "toolName": "run_command",
  "commandPrefix": "pnpm test"
}

    安全兜底

    • deny 规则、PreToolUse Hook、workspace ACL 和灾难命令黑名单始终生效。
    • 命令还受超时、CPU、输出大小、文件大小和平台沙箱限制。
    • 部分隔离不会被包装成完整沙箱；严格隔离需要 Docker/VM 或受支持的平台后端。
    14 / HOOKS

    Hooks：把团队规则放进执行链

    支持的生命周期

    事件用途拒绝效果
    SessionStart环境检查、策略初始化撤销新会话
    UserPromptSubmit阻止敏感 prompt 或注入补充规则消息不落盘
    PreToolUseallow / ask / deny 工具调用工具不执行
    PostToolUse日志、指标、附加审计只观察
    Stop完成前检查验证与交付条件阻止 turn 完成

    hooks.json 示例

    {
  "hooks": [
    {
      "id": "guard-destructive-commands",
      "event": "PreToolUse",
      "matcher": "run_command",
      "command": "node ./.clawsmith/hooks/guard-command.mjs",
      "enabled": true,
      "trusted": true,
      "timeoutMs": 5000,
      "conditions": {
        "risks": ["execute"],
        "permissionModes": ["default", "accept-edits"],
        "pathPrefixes": ["packages/", "infra/"]
      }
    }
  ]
}

    Hook 输出契约

    {
  "decision": "deny",
  "reason": "Do not deploy from a local interactive turn."
}

    Hook 通过 stdin 接收结构化 context。除 PostToolUse 和 PostCompact 外，失败、超时或非法 JSON 都按拒绝处理； 结果写入 hook-audit.jsonl。

    15 / SESSIONS

    会话、队列与失败恢复

    Session 是持久事实源。消息、事件、工具状态、审批、usage、计划、目标、 checkpoint、队列和 artifact 都从 SQLite/文件存储恢复，客户端内存不是事实源。

    Lease 与多客户端

    • 同一 Session 通过 lease 限制单写者；多客户端看到相同事件序列。
    • 失败 turn 保留最后成功步骤和 pending tools；未知副作用禁止自动重放。
    • Web 可停止后继续新 turn；CLI 使用 /resume-turn 和显式确认恢复。
    • 会话支持 JSON/JSONL 导出、workspace 集合导出、严格校验导入和生命周期清理。

    运行中追加约束

    /queue "补充：不要修改公开 API"
/queue redirect "先停止当前方案，改为保留旧接口"

    queue 在下一模型步骤执行；interrupt-and-redirect 只中止当前安全边界内的 turn， 新 turn 仍会重新经过权限、验证和预算检查。

    诊断与恢复入口

    /resume-turn
/resume-turn confirm
/requests
/requests snapshot <request-id>
/diagnostics
    16 / RECOVERY

    失败恢复与未知副作用

    失败分类

    turn 会区分 model、tool、approval、lease lost、process exit、unknown side effect、 aborted、iteration limit、resource limit 和 verification 失败。分类写入事实源， 客户端不根据错误文本猜状态。

    可安全继续的情况

    • 没有执行副作用工具，或工具已经得到可信成功结果。
    • 只是模型流断开、租约恢复或客户端重连。
    • checkpoint 已证明当前文件与预期状态一致。

    必须人工确认的情况

    命令、外部写入、MCP mutation 或消息发送在进程退出时没有结果，会标记为 unknown。先检查工作区、日志和外部服务，再使用 /resume-turn confirm；系统不会自动重放。

    30 / CUSTOM TOOL

    编写自定义 Tool 插件

    完整工具定义

    工具必须有稳定名称、Zod v4 输入 schema、风险级别、能力声明、并发安全性和 摘要函数。执行函数只能实现业务动作；审批、超时、取消和结果持久化仍由 Core 管理。 

    import { PLUGIN_API_VERSION, type PluginModule } from "clawsmith/plugin-api"
import { z } from "zod"

const plugin: PluginModule = {
  apiVersion: PLUGIN_API_VERSION,
  apply(ctx) {
    return ctx.tools.register({
      name: "issue_lookup",
      description: "Look up one issue in the team issue tracker",
      inputSchema: z.object({
        id: z.string().min(1),
      }),
      risk: "read",
      capabilities: ["network", "session.read"],
      concurrencySafe: true,
      summarize: (input) => {
        const { id } = input as { id: string }
        return `Look up issue ${id}`
      },
      async execute(input, { signal }) {
        const { id } = input as { id: string }
        const response = await fetch(
          `https://issues.example/api/issues/${encodeURIComponent(id)}`,
          { signal },
        )
        if (!response.ok) throw new Error(`Issue lookup failed: ${response.status}`)
        return response.json()
      },
    })
  },
}

export default plugin

    字段如何影响 Agent

    字段用途与约束
    riskread、workspace-write 或 execute；决定权限最低风险等级。
    capabilities声明网络、文件、凭据或外部副作用；只能用于收紧策略，不会自动授予权限。
    concurrencySafe只有可并行调用时才设为 true；有共享写入或限流状态时应串行。
    summarize生成审批和轨迹中的短摘要，不得包含密钥或大段外部正文。
    signal用户取消或超时时必须中止 fetch、子进程和其他外部请求。

    编写自定义 Provider

    实现统一流协议

    Provider 按能力实现 stream()，把供应商 SSE 或本地推理输出转换成统一事件： text.delta、reasoning.delta、 tool_call.completed、usage 和 response.completed。不要在 Provider 内执行工具。 

    import { PLUGIN_API_VERSION, type PluginModule } from "clawsmith/plugin-api"

const plugin: PluginModule = {
  apiVersion: PLUGIN_API_VERSION,
  apply(ctx) {
    return ctx.models.register({
      id: "team-gateway",
      models: ["team-reasoner"],
      getModelCapabilities() {
        return {
          contextWindowTokens: 128_000,
          contextWindowKnown: true,
          maxOutputTokens: 16_384,
          supportsTools: true,
          supportsImages: false,
          supportsStreaming: true,
          supportsReasoning: true,
          usageReporting: "supported",
          source: "static",
        }
      },
      async *stream(request) {
        if (request.signal.aborted) return
        yield { type: "text.delta", text: "adapter response" }
        yield { type: "response.completed", finishReason: "stop" }
      },
    })
  },
}

export default plugin

    生产适配器必须处理什么

    • 透传 request.signal，取消后立即停止读取网络流。
    • 保留 tool call 参数直到完整，再发出一个结构化 tool call 事件。
    • 只有上游提供 usage 时才发 usage；未知不能被当成 0 token 或免费。
    • reasoning、图片、原生文档和并行工具调用要通过能力元数据显式声明。
    • 供应商错误转换为稳定错误类别，不把认证 header 或响应正文写入日志。

    路由与 failover

    模型 ID 必须由活动 Provider 声明。同一模型有多个 Provider 时，路由可按配置顺序 failover；只有在任何流事件输出前失败才能切换。一旦已输出文本或 tool call， 系统不会重放请求，避免重复 token 和重复副作用。

    统一消息链路

    当前产品只内置微信、QQ、Email；其它 IM 平台不进入核心实现，后续通过插件 API 接入。平台 adapter 只负责认证、原始事件规范化、发送和可选的原生交互；Gateway Runtime 统一处理配对、ACL、delivery 幂等、Session 绑定、typing 生命周期、审批、 澄清、失败恢复和 Profile 隔离。 

    platform event
  → adapter authentication + normalization
  → Gateway pairing / DM / group policy
  → SQLite delivery idempotency
  → ordinary Clawsmith Session + Agent Core
  → typing heartbeat / progress
  → approval or clarification through the same platform
  → redacted final reply or failure

    微信和 Email 通过文本 approve / deny 完成审批；QQ 使用 原生“允许一次 / 拒绝”按钮，同时保留文本兜底。Email 审批只读取正文首个非空行， 邮箱签名和引用内容不会影响命令识别。turn 执行期间 Host 会周期刷新 typing，并在完成、失败或取消后停止输入状态。超时、发送失败或未配对用户响应时 都会按拒绝处理。进程在副作用执行中退出时，遗留 delivery 标记为 unknown，不会自动重放。

    模型调用 ask_user_question 时，三个平台都能接收澄清回答。微信和 Email 使用编号或选项名，允许自由回答的问题也可以直接回复文本；QQ 显示原生选项 按钮和取消按钮。回答绑定当前 sender 与 Session，未配对用户不能替其它成员选择。

    “消息平台”设置页还展示运行诊断：Typing 心跳成功/失败、澄清完成/失败，以及最近 最终回复的 delivered、pending、failed 和 unknown 聚合。诊断不包含消息正文、 凭据或平台原始响应，便于区分“连接正常”和“回复投递降级”。 

    CLAWSMITH_GATEWAY_LIVE_SMOKE=1 \
CLAWSMITH_GATEWAY_SMOKE_PLATFORMS=wechat,qq,email \
pnpm smoke:gateway

    真实凭据 smoke test 只做认证和连接探测，不发送业务消息，也不会进入默认 CI； 未配置的平台会明确显示 SKIP。

    最终回复使用独立 SQLite 投递账本。Host 在调用平台前保存 pending，调用时 标记 attempting，平台确认后才标记 delivered。重启只会重发 pending；进程在 attempting 中退出时转为 unknown， 不会因为无法确认平台是否收到而盲目重复发送。

    Agent 主动发送

    Session 进入外部会话后，Agent 可使用 list_message_targets 查看当前会话 已绑定目标，并使用 send_message 主动通知。发送属于外部副作用，必须经过 普通工具权限审批；目标只能来自既有 Gateway binding，不能由模型任意指定新地址。 可通过 attachments 传入当前 workspace 内的相对路径，单文件上限 20 MB、 总量上限 50 MB。微信会走 iLink 加密 CDN，QQ 使用 RichMedia 分片上传，Email 使用 MIME 附件；符号链接逃逸工作区的文件会被拒绝。

    每个平台还可配置“默认通知会话 / 默认通知邮箱”。它作为 Home Channel 出现在消息目标 列表中，供 Cron、通知和没有当前 binding 的主动发送复用。

    3. 处理入站与回复

    • 把平台事件转换为最小 GatewayInboundMessage，不要让原始 JSON 进入 Agent。
    • platformHint 只描述平台输出能力，不包含凭据、用户数据或绝对路径；它会随消息目标提供给模型。
    • deliveryId 使用平台事件 ID；重复投递必须返回同一结果。
    • conversationId 标识稳定会话，senderId 标识自然人。
    • deliver() 只发送终态或脱敏失败说明，不发送工具参数和内部事件。
    • deliver() 确定未发送时抛出 GatewayDeliveryError(kind="not-sent")；响应丢失或连接中断保留默认 ambiguous，不要自动重发。
    • 长轮询/WebSocket 在 start() 建立，在 stop() 完整释放。
    • 平台支持原生审批时实现 requestApproval()；否则 Host 默认拒绝。
    • 实现 typing() 后 Host 会周期刷新；支持关闭状态的平台再实现 stopTyping()。
    • 实现 requestClarification() 接收模型选择问题；回答必须绑定当前 sender、会话和 Session。
    • checkDependencies() 在启动前探测依赖；失败时用 installHint 告知安装方式。
    • setupSteps 显示在 Web 表单上方；通用字段表单和扫码登录共同组成 setup 流程。
    • 实现 rewire() 以幂等重绑动态加载的 native client handler。
    • customTargets 必须同时实现目标解析和校验；模型仍只能向既有 binding/home target 发送。
    • 入站媒体放入 attachments；下载前先调用 startContext.authorize() 做配对/ACL 预检。
    • 扫码或设备码登录实现 login.begin()/poll()，凭据只通过 poll 返回值交给 Host。

    40 / PROFILES

    Profile 身份隔离

    隔离边界

    Profile 是会话、Provider 凭据、记忆、Skill、后台任务和数据的硬隔离边界。 Profile 切换只影响新进程；运行中的服务不会热切换数据库或凭据。 

    clawsmith profile create work --name "Work identity"
clawsmith profile use work
clawsmith profile list
clawsmith profile current
CLAWSMITH_PROFILE=work clawsmith web

    临时覆盖

    CLAWSMITH_PROFILE 只覆盖当前进程，不修改持久 active pointer。 未知或已归档 Profile 会 fail closed。需要让 CLI、Web、Cron 和 Gateway 使用同一 身份时，为这些进程设置相同值并分别启动。

    同一 Profile 只运行一个 Server

    serve 和 web 会在打开 SQLite 与启动消息平台之前抢占 当前 Profile 的运行时租约。再次启动同一 Profile 不会创建第二个 Core，而是输出 已有实例的 URL 和 PID： 

    clawsmith web
# Clawsmith is already running ... at http://127.0.0.1:3210/

# 只有需要主动替换现有实例时才使用：
clawsmith web --replace

    常规启动不会终止现有进程。--replace 会先发送 SIGTERM，等待旧实例 释放 SQLite、Cron 和 Gateway；超时不会强制误杀。PID 已消失的僵尸租约会在下一次 启动时自动回收，仍存活的进程不会被普通启动抢走。

    多个 Profile 并行

    每个 Profile 使用独立状态根和运行时租约，因此可以同时运行多个长期 Server： 

    clawsmith web --env production
CLAWSMITH_PROFILE=coder clawsmith web --env production
CLAWSMITH_PROFILE=writer clawsmith web --env production

    这些进程共享安装代码，但不共享 Session、Memory、Provider 凭据、Cron 或 Gateway 数据。当前推荐拓扑仍是一个 Profile 一个 Server 进程；单个进程 multiplex 全部 Profile 的执行合并属于后续能力。

    单端口访问多个 Profile

    使用 --all-profiles 启动共享 HTTP 入口。它会发现所有未归档 Profile， 默认路径指向启动该命令的 Profile，前缀路径路由到对应 Profile： 

    clawsmith web --all-profiles

GET /health                  -> 当前启动 Profile
GET /p/work/health           -> work Profile
GET /p/work/sessions         -> work Profile 的会话 API
GET /p/work/sessions/:id/stream?after=42

    默认情况下，所有 Profile Host、Cron 和 Gateway 运行在同一个 OS 进程内，但每个 Profile 仍拥有独立 Core、认证、SQLite、Gateway 和插件 scope。系统只监听一个 公共端口，请求通过内存 handler 分派；Cron 也由一个共享 ticker 调用各 Profile。 需要故障隔离和自动重启时使用 --all-profiles --isolated-profiles 切换到每 Profile 独立子进程。 重复启动返回已有 URL，--replace 接管整个共享入口。

    Web 顶部提供 Profile 选择器。切换后写入 clawsmith_profile 同站 Cookie 并刷新，未加前缀的 API 会跟随当前 选择；显式 /p/<profile>/ 始终优先。选项同时显示启动、就绪、 重启中或失败状态以及重启尝试次数。

    选择器可单独停止和重新启动非 Launch Profile，也可以重启当前 Profile。停止一个 Profile 不会影响其他 Profile；Launch Profile 停止会导致公共入口失去默认路由， 因此只能通过共享入口的 --replace 整体重启。

    LOOPBACK

    多 Profile 共享入口当前只监听本机地址。远程访问应在它前面部署认证反向代理， 或通过 SSH 端口转发；默认同进程模式没有内部 Profile listener 端口。

    消息平台凭据独占

    不同 Profile 可以使用相同平台，但不能使用同一个 Bot 凭据同时轮询。微信按 account/token、QQ 按 App ID/Secret、Email 按邮箱/密码建立跨 Profile 独占租约； Slack 插件加载后按 Bot Token 使用同一租约机制。 

    Profile coder  -> wechat / credential A  ✓
Profile writer -> wechat / credential A  ✗ already in use by coder
Profile writer -> wechat / credential B  ✓

    凭据原文只参与本地 SHA-256，不会写入锁文件、日志、API 或错误消息。冲突只停止 对应 adapter，其他 Profile 和其他聊天平台继续运行。自定义轮询 adapter 应实现 getCredentialIdentity()，返回平台 scope 和凭据组合。

    归档与删除

    归档保留可恢复数据；删除属于独立高风险操作，要求显式确认。代码插件 Profile （CLAWSMITH_PLUGIN_PROFILE）只负责组件组合，不等同于身份 Profile， 不能替代凭据和数据隔离。

    安全与部署

    默认安全边界

    • 默认只监听 loopback；远程监听必须显式开启并提供强 token。
    • 生产环境建议由反向代理终止 TLS，不要通过不可信网络明文发送 token。

    • 命令子进程使用最小环境变量，不继承宿主 API Key。
    • 日志、事件、工具结果、导出和 artifact 使用统一脱敏边界。
    • 企业 managed policy 可强制 deny、收紧权限模式、预算和更新 channel。

    命令与桌面隔离

    命令子进程只继承最小环境变量，不继承宿主 Provider Key。macOS 使用 sandbox-exec，Linux 使用 bwrap，Windows 原生 ACL 只提供兼容级部分隔离；严格隔离应显式选择 Docker、VM 或远程 Execution World。

    44 / DATA LIFECYCLE

    导出、备份与清理数据

    导出单个会话

    /export ./exports/session.json
/export ./exports/session.jsonl --jsonl
/export ./exports/session-with-files.zip --attachments

    默认导出排除凭据、图片与附件正文、artifact 正文、Memory、Skill、待审批请求和 宿主绝对路径，并写入格式版本与 SHA-256。--attachments 会包含当前消息 实际引用的附件，文件可能含敏感内容，应单独加密和限制访问。

    导入与迁移

    /export-workspace ./exports/workspace.zip
/import ./exports/session.json
/import ./exports/workspace.zip

    导入会重新校验格式版本、体积、消息/事件数量和摘要，并生成新 session ID，不会覆盖 已有会话；失败时删除半导入数据。JSONL 每行承载一条消息、事件或附件，适合流式传输。

    预览后清理

    /cleanup-preview 2026-01-01T00:00:00Z
/cleanup 2026-01-01T00:00:00Z --workspace <workspace-id> --yes

    预览会列出会话、更新时间、逻辑可释放字节、共享附件引用和不可清理原因。活动 turn、 跨进程 lease、SessionEnd Hook 失败或共享附件仍被引用时不会删除。artifact 默认 保留 7 天，并受会话级与全局容量淘汰约束。

    数据库备份

    /backup ./backups/clawsmith.sqlite
clawsmith restore ./backups/clawsmith.sqlite

    backup 使用 SQLite 一致性备份并做完整性检查。restore 会保留恢复前的安全副本； 它不是云备份，也不包含未纳入数据库的工作区文件、附件正文或远端系统状态。

    45 / QUALITY

    测试、评测与发布门禁

    提交前验证

    pnpm check
pnpm verify:package
pnpm verify:package:publish
pnpm test:e2e
pnpm eval:smoke:verify
pnpm bench:resources:verify

    pnpm check 覆盖 lint、类型检查、Vitest 和 local build； package 验证必须测试真实 tarball，而不是源码运行结果。评测记录 pass@K、 false-done、工具错误、恢复成功率、token、成本与首 token 延迟。

    评测回归

    pnpm eval:agent --runs 3
pnpm eval:compare baseline.json current.json \
  --min-pass-rate 0.9 \
  --max-false-done-rate 0.05 \
  --max-tool-error-rate 0.15

    评测在隔离工作区内运行构建产物，并与基线比较通过率、pass@K、恢复率、成本、 false-done 和工具错误率。真实模型评测需要显式配置 Provider，默认 CI 使用 mock。

    46 / RELEASE

    发布与供应链验证

    生成可验证发布证据

    pnpm release:verify
pnpm release:prepare --output release-artifacts --tag v0.1.7

    prepare 会依次运行源码检查、local tarball、publish 构建、精确 tarball 安装验证、 生产依赖 audit 和许可证检查。输出包含 package manifest、SHA 摘要、CycloneDX SBOM、 第三方许可证、audit 结果和 release notes。

    版本与 tag 约束

    • package.json.version 必须严格等于 tag 去掉 v 后的版本。
    • CHANGELOG.md 必须恰好包含该版本的一个发布段落。
    • tag 必须位于 origin/main 历史中。
    • 上传前的 tarball 摘要必须与 prepare 阶段记录的摘要一致。

    npm 身份与 provenance

    CI 使用受保护的 npm-publish Environment 和 npm Trusted Publisher， 通过 GitHub OIDC 获取短期身份，不依赖长期 NPM_TOKEN。首次 tag 发布后 要检查 provenance 指向当前仓库、workflow 和 commit。

    LICENSE

    --access public 只表示 npm 包可公开下载，不改变仓库许可证。 当前项目仍是专有软件；开源前必须单独完成许可证和发布策略调整。

    49 / ENVIRONMENT

    环境变量参考

    运行位置与身份

    变量用途
    CLAWSMITH_HOME覆盖配置、会话、凭据、插件和 artifact 的数据根目录。
    CLAWSMITH_PROFILE为当前进程选择身份 Profile；不修改持久 active pointer。
    HOST / PORTWeb 与 HTTP 服务监听地址和端口，默认 loopback 与 3210。
    CLAWSMITH_ALLOW_REMOTE必须设为 1 才允许非 loopback 监听。
    CLAWSMITH_API_TOKEN远程访问的首次引导 token；非 loopback 时至少 32 字符。
    CLAWSMITH_DISABLE_UPDATE_CHECK临时关闭版本更新检查。
    CLAWSMITH_MANAGED_POLICY_FILE加载企业 managed policy，强制收紧权限、预算和更新策略。

    模型与上下文

    变量用途
    CLAWSMITH_PROVIDER_BASE_URL当前 Provider 的 OpenAI-compatible API 根地址。
    CLAWSMITH_PROVIDER_MODEL默认模型 ID。
    CLAWSMITH_PROVIDER_API_KEY临时 Provider 密钥；生产环境优先使用安全凭据存储。
    CLAWSMITH_PROVIDER_CONFIG_HOME隔离或共享 Provider 配置文件根目录。
    CLAWSMITH_DEFAULT_MODEL新会话默认模型；可配合自动路由策略。
    CLAWSMITH_ROUTING_POLICY_PATH模型自动路由策略 JSON 路径。
    CLAWSMITH_MODEL_TEMPERATURE覆盖采样温度；省略时使用 Provider 默认值。

    CLAWSMITH_MODEL_STREAM_IDLE_TIMEOUT_MS中止长时间无新事件的模型流。
    CLAWSMITH_CONTEXT_WINDOW_TOKENS显式覆盖未知模型上下文窗口，范围 500 到 2,000,000。
    CLAWSMITH_SEMANTIC_COMPACTION设为 0 时关闭额外模型摘要压缩。

    执行、插件与外部入口

    变量用途
    CLAWSMITH_SANDBOX_MODEcompatible、strict 或 isolated；不满足能力时拒绝启动。
    CLAWSMITH_SANDBOX显式选择 docker 等命令沙箱后端。
    CLAWSMITH_EXECUTION_WORLD选择本地、Docker、SSH 或插件提供的 Execution World。
    CLAWSMITH_PLUGIN_RUNTIME设为 1 启用公开插件 runtime 和动态模型路由适配。
    CLAWSMITH_PLUGIN_PROFILE选择插件 Profile；与身份 CLAWSMITH_PROFILE 不同。
    CLAWSMITH_PLUGIN_PATCH本次进程最高优先级的插件 overlay 文件。

    CLAWSMITH_WECHAT_TEXT_BATCH_DELAY_SECONDS / CLAWSMITH_WECHAT_TEXT_BATCH_SPLIT_DELAY_SECONDS快速文本合并窗口和长消息续块等待窗口，单位为秒。
    CLAWSMITH_QQ_APP_ID / CLAWSMITH_QQ_CLIENT_SECRET从环境引导 QQ 官方 Bot API v2。
    CLAWSMITH_QQ_DM_POLICY / CLAWSMITH_QQ_GROUP_POLICYQQ 平台级访问策略和白名单入口。
    CLAWSMITH_QQ_HOME_CONVERSATIONQQ 默认通知目标，格式为 c2c:、group: 或 guild:。
    CLAWSMITH_QQ_MARKDOWN_SUPPORTQQ C2C 和群聊是否使用原生 Markdown，默认开启；设为 0 时发送清理过格式的纯文本。
    CLAWSMITH_EMAIL_ADDRESS / CLAWSMITH_EMAIL_PASSWORDEmail 账号和应用专用密码。
    CLAWSMITH_EMAIL_IMAP_HOST / CLAWSMITH_EMAIL_SMTP_HOSTEmail 收件 IMAP 和发件 SMTP 主机。
    CLAWSMITH_EMAIL_DM_POLICY / CLAWSMITH_EMAIL_ALLOWED_SENDERSEmail 入站策略与发件人白名单。

    managed hard policy
  → explicit process environment

    50 / TROUBLESHOOTING

    常见问题

    Web 打不开或远程连接被拒绝

    默认只监听 127.0.0.1。远程访问需要 HOST=0.0.0.0 CLAWSMITH_ALLOW_REMOTE=1 和强 token；建议通过反向代理启用 TLS。

    Agent 反复要求审批

    查看当前权限模式和持久规则。命令前缀、路径前缀、tool 名和 Hook 都可能把 allow 收紧为 ask/deny；allow-all 仍会触发二次确认。

    命令或子 Agent 状态是 unknown/orphaned

    宿主在副作用执行期间退出时，系统不会自动重放。检查工作区、日志和外部系统后， 再显式恢复或重新发起任务。
