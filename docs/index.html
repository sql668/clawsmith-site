    clawsmith 是什么

    clawsmith 是运行在本机的 coding agent。它读取真实项目、搜索代码、修改文件、执行命令， 并要求在修改工作区后取得验证证据。CLI 和 Web 不是两套产品：两者共享同一套 Agent Core、SQLite 会话、审批、场景、团队任务和 Workflow 状态。

    你负责 clawsmith 负责 系统保留的证据
    描述目标、约束和验收方式 读取项目、选择工具、执行修改和测试 消息、事件、工具结果和 usage
    审批风险动作 检查参数、路径、权限和沙箱 审批审计、命令输出和检查点
    审阅最终结果 运行验证、汇总 blocker 和产物 changed files、artifact 和 journal
    LOCAL ≠ OFFLINE

    会话、记忆、Skill 和权限默认保存在本机，但真实模型请求会发送到你配置的 Provider。选择 Provider 前先确认其数据处理与保留策略。

    环境要求

    项目 要求 说明
    Node.js 22.13 或更高 CLI 和 Server 会在加载主程序前检查版本。
    系统 macOS / Linux / Windows 其他平台会得到明确错误，不静默尝试。
    包管理器 npm 或 pnpm 安装后的命令名始终是 clawsmith。
    模型服务 OpenAI-compatible API 未配置时可使用离线 Demo，但不能完成真实代码任务。

    安装与升级

    1. 安装 npm 包 
      npm install -g clawsmith
clawsmith --version

      从旧的 @shiql/mx-claw 迁移时，新命令是 clawsmith。若 ~/.clawsmith 尚不存在，启动会继续复用 旧 ~/.mx-claw 中的 Provider、密钥、会话和检查点。

    2. 或者临时运行，不写入全局包目录 
      npx clawsmith@latest --version
    3. 需要升级时直接覆盖安装 
      npm install -g clawsmith@latest
clawsmith --version

      覆盖安装不会删除 ~/.clawsmith 中的 Provider、密钥、会话、检查点或 Agent 定义。

    UPDATE CHECK

    交互式 CLI 和 clawsmith web 会在启动时检查 npm latest，最多等待 1.5 秒。你可以只跳过一个版本；更高版本发布后仍会再次提示。

    第一条任务

    第一次使用建议先打开 Web 面板。可视化工作区选择、模型配置和审批更容易确认。 

    clawsmith web
# http://127.0.0.1:3210
    1. 添加工作区

      点击左侧工作区旁的“+”，选择本地项目。工作区决定文件访问和项目记忆边界。

    2. 配置模型

      打开“设置 → 模型”，填写 Provider、Base URL、模型列表和 API Key，保存后将可用 Provider 设为默认。

    3. 提交一个容易验证的小任务

      例如：“阅读项目入口和测试脚本，告诉我应用如何启动。不要修改文件，并列出你检查过的路径。”

    4. 核对回答和证据

      展开工具按钮查看真实读取结果；确认回答中的路径、命令和项目一致后，再让 Agent 执行写任务。

    成功标准：模型返回结果，工具输出可展开，会话刷新后仍然存在。

    配置模型

    Provider 是连接信息，模型是当前会话的推理选择。切换模型不会扩大工具或权限边界。 

    /model status
/model list
/model configure openai
/model default openai/gpt-4o-mini
/model use openai/gpt-4o-mini
/model refresh
    入口 用途 作用范围
    clawsmith → /model 配置 Provider、保存 API Key、刷新模型目录 全局 Provider 配置
    /model use provider/model 切换当前会话模型 当前 session
    Web“设置 → 模型” 管理 Provider、默认模型和健康状态 所有 CLI/Web 进程共享配置
    SECRET

    API Key 不会回显到 Web 页面、会话或日志。它优先进入系统 Keychain / Secret Service，无法使用时才进入加密文件；普通 config.json 不保存明文。

    CLI 工作流

    在项目根目录运行 clawsmith。当前目录会成为默认工作区。

    cd ~/projects/my-app
clawsmith

# 也可以不进入 REPL，直接提交一次任务
clawsmith --permission-mode plan \
  --prompt "分析测试失败，给出最小修复方案"

    推荐的任务表达

    GOOD PROMPT

    “先读取 src/auth 和现有测试，定位登录超时原因。只修改认证模块， 补一个回归测试，最后运行 pnpm test。如果测试失败，保留完整错误并停止。”

    同时给出范围、禁止项和验证命令。不要只说“优化一下”或“把项目修好”，否则你很难判断 Agent 是否扩大了修改范围。

    会话与审批

    • 只读工具通常直接执行；写文件和有副作用命令按权限模式请求审批。
    • 输入允许或拒绝后，结果进入同一持久 transcript 和审批审计。
    • 关闭终端不会删除会话；重新打开 CLI 后可用 /resume 选择旧会话。
    • 输入 /help 查看当前命令；输入 /exit 退出。

    Web 工作台

    clawsmith web
# 默认 http://127.0.0.1:3210

PORT=3220 HOST=127.0.0.1 clawsmith web
    区域 适合做什么 注意事项
    左侧工作区与会话 创建项目、切换会话、查看运行状态 工作区是文件与项目记忆的 ACL 边界。
    中间对话与审批 阅读回答、展开工具结果、批准或拒绝动作 工具结果使用小按钮，点击后查看完整输出。
    会话用量与检查点 查看 token、上下文占用和可恢复回合 检查点按钮打开弹窗，不再占用消息流。
    设置 模型、Agents、团队、Workflow、记忆、技能、设备和安全 所有配置最终仍由本地 Server 和 SQLite 校验。

    Web 常用操作

    • 输入 /providers 打开模型管理。
    • 输入 /permissions 打开权限管理，或在输入框旁切换会话权限。
    • 输入 /scene coding 切换场景；输入 /new 开始新会话。
    • 回答中的代码块默认展开，可收起后复制；思考过程和工具详情按需展开。
    • 右上角“导出会话”生成脱敏后的会话包，默认不包含密钥和 artifact 正文。

    权限与审批

    模式 适合场景 变更动作
    plan 先理解仓库、做只读方案 只读，拒绝写入和变更命令
    default 日常人工监督 写文件和不确定命令逐次审批
    accept-edits 信任当前工作区编辑 自动接受文件写入，命令仍需审批
    unattended 无人值守，但只允许确定安全动作 无法确认的动作直接拒绝
    allow-all 受信任隔离环境 二次确认后跳过常规审批，硬边界仍生效
    ALLOW-ALL ≠ UNRESTRICTED

    显式 deny、灾难命令拦截、工作区路径、Hook、输出限制和平台沙箱不会因为 allow-all 自动关闭。

    场景模式

    场景决定角色、阶段、输出契约和返工上限，不授予额外工具或权限。新会话默认使用 general。 

    /scene
/scene coding
/scene blog
/scene brainstorm
/scene coding run 为解析器补错误分支和测试
/scene blog run 写一篇项目架构说明
/scene brainstorm run 设计离线同步方案
    场景 执行路径 适合任务
    general 原有直接 Agent 循环 不需要固定多角色流程的任务
    coding fast / complex / repair 小修、复杂重构、修复 blocker
    blog standard / research / repair 大纲、可选调研、正文和审稿
    brainstorm 三方向发散、挑战、收敛、repair 产品方向、架构方案、取舍分析

    切换场景会保存在当前会话中，CLI 和 Web 刷新后读取同一个值。活跃 turn 或跨进程 租约存在时不能切换。

    Agent 定义

    Agent 定义保存在 ~/.clawsmith/agents/active/<id>/AGENT.md。首次启动会安装 Coding、Blog 和 Brainstorm 内置角色，但不会覆盖你修改过的文件。 

    /agents
/agents list
/agents show coding-tester
/agents disable coding-tester
/agents enable coding-tester
    ROLE

    职责写在正文

    AGENT.md 的正文成为角色 system prompt，说明允许目标和禁止行为。

    BOUNDARY

    能力只能收窄

    工具、Skill、Hook、写路径、命令前缀和权限不能超过父 Agent 或运行时上限。

    WEB

    Web“设置 → Agents”展示角色、版本、工具、权限和启停状态。禁用角色后，新的 delegate 或 Workflow step 不能继续使用它。

    Goal 与 Plan

    长任务先固定目标，再提交计划。只要存在待审批 plan，写文件和变更命令会在权限判断前 被拒绝。 

    /plan set 在不改变公开 API 的前提下收敛认证实现
/plan submit {"scope":"认证模块","steps":[{"title":"盘点重复实现","description":"读取调用链和测试","expectedChanges":["src/auth/"],"risks":["遗漏外部调用"],"verification":"pnpm test"}],"expectedChanges":["src/auth/"],"risks":[],"verification":["pnpm test"],"openQuestions":[]}
/plan approve <plan-id>
/plan complete pnpm check 通过，changed files 已审阅
    • 变更 goal 递增 revision，并把旧 pending/approved plan 标为 superseded。
    • 批准 plan 只表示允许开始执行，不创建永久 allow 规则。
    • 完成 goal 必须提交非空证据，模型自然语言不能直接关闭目标。

    团队任务与 Workflow

    /team 管理任务图；/workflow 运行声明式 DAG。正常情况下， 场景会自动生成 Workflow，你只在需要手动编排或排查时直接操作它们。 

    /team
/team add 实现缓存层 --after design --write src/cache/
/team claim <task-id> coding-implementer 300000
/team complete <task-id> coding-implementer <version> 实现并验证完成

/workflow
/workflow start ./workflow.json --input "补齐回归测试"
/workflow run <run-id>
/workflow journal <run-id>
/workflow pause <run-id>
/workflow resume <run-id>
/workflow cancel <run-id> "需求变更"
    对象 回答的问题 持久事实
    Todo 模型认为做到哪一步 session_todos
    TeamTask 谁在何时能安全执行这个节点 owner、blockedBy、writeSet、claim、version
    WorkflowRun 整个多阶段流程进行到哪 nodeStates、预算、终态和 Run lease
    Journal 状态为什么变化 append-only step/run 事件
    UNKNOWN

    有副作用的步骤开始后进程退出，会停在 unknown。先检查工作区、命令和 外部服务，再决定修复；系统不会自动重放。

    记忆与 Skill

    只有明确说“记住”的请求才生成长期记忆候选。候选经过审核后才进入后续会话；当前会话 已冻结的记忆快照不会自动刷新。 

    /memory remember 项目约定 :: 提交前必须运行 pnpm check
/memory search 发布流程
/memory forget <id>
/skills pending
/skills approve <id>
/skills archive <id>

    Web“设置 → 记忆”支持筛选、编辑、来源查看、归档和恢复；“设置 → 技能”支持批准、 拒绝、归档与恢复。记忆和 Skill 仍然是普通上下文，不能修改权限、Hook 或沙箱。

    长任务与 PTY

    开发服务器、watch、长构建和需要交互的终端任务使用后台命令，不占用当前回答。 

    /commands
/commands capabilities
/commands status <task-id>
/commands log <task-id>
/commands input <task-id>
/commands resize <task-id> 120 40
/commands cancel <task-id>
    • 普通命令与 PTY 使用同一个 task ID 和增量日志模型。
    • POSIX PTY 需要 Python 3；Windows PTY 依赖可选 node-pty/OpenConsole。
    • Windows sandboxed PTY 当前 fail closed；普通后台命令仍可用。
    • Web“设置 → 长任务”可查看输出、输入、尺寸和取消。

    恢复与回退

    先区分“模型/审批失败”和“副作用未知”。前者可以从持久检查点继续；后者必须先检查现场。 

    /status
/requests <turn-id>
/resume-turn
/resume-turn confirm
/undo list
/undo diff <turn-id> src/auth/session.ts
/undo session <turn-id>
/undo all <turn-id>
/diagnostics
    恢复范围 会改变什么 不会做什么
    仅文件 按 checkpoint 恢复文件 before 状态 不会回退对话
    仅会话 回退消息、事件、todo 和待审批边界 不会修改工作区文件
    全部 先预检冲突，再恢复文件与会话 外部修改冲突时整批停止

    Web 的会话累计行提供“检查点 · N”按钮。弹窗中可查看关联请求、文件 diff、 时间、turn ID 和恢复动作；输入框上方行宽按内容收缩。

    远程访问与设备

    默认只监听 loopback。需要从另一台设备访问时，至少设置 32 字符 owner token，并让 应用继续位于 TLS 终止代理之后。 

    export CLAWSMITH_API_TOKEN="$(openssl rand -hex 32)"
HOST=0.0.0.0 CLAWSMITH_ALLOW_REMOTE=1 clawsmith web

    登录后可在“设置 → 设备”配对 operator 或 viewer。viewer 只能读取授权 workspace， 撤销设备后它的 Cookie 和 Bearer 立即失效。

    NETWORK

    不要把明文 HTTP 端口直接暴露到不可信网络。远程访问仍建议使用 TLS 代理、 最小 workspace 授权和可撤销设备 token。

    SDK 与协议

    TypeScript SDK 封装协议协商、SSE、sequence 去重、审批、取消和 artifact 读取。 协议 v21 保持最低客户端 v20 的兼容窗口。 

    import { ClawsmithClient } from 'clawsmith/sdk'

const client = new ClawsmithClient({
  baseUrl: 'http://127.0.0.1:3210',
})
const session = await client.createSession({ title: 'SDK task' })

let lastSequence = 0
for await (const event of client.submitTurn(session.sessionId, task)) {
  lastSequence = event.sequence
}

    客户端不应自行推导“任务完成”。终态以 turn.completed、 turn.failed 或 turn.cancelled 为准；终态事件始终是最终事实。

    更新与版本

    启动检查只读取 npm 的 latest dist-tag。网络失败、CI 和非交互终端会静默跳过， 不会阻止 Agent 启动。 

    # 查看当前版本
clawsmith --version

# 覆盖升级
npm install -g clawsmith@latest

# 暂时关闭启动检查
CLAWSMITH_DISABLE_UPDATE_CHECK=1 clawsmith

# 确认实际命中的全局安装
command -v clawsmith
Get-Command clawsmith   # Windows PowerShell
    • “跳过该版本”只屏蔽当前检测到的 latest；更高版本仍会提醒。
    • 覆盖安装不会删除 CLAWSMITH_HOME 中的配置和会话。
    • 安装后仍是旧版时，通常是 PATH 中命中了另一套全局安装。

    常见问题排查

    现象 先检查 处理
    启动提示 Node 版本不足 node --version 升级到 22.13+，再重新运行。
    升级后仍显示旧版本 command -v clawsmith 清理实际命中的重复全局安装并覆盖安装。
    Web 只显示 Demo “设置 → 模型”的 Provider 状态 配置 Base URL、模型和 Key，并把 Provider 设为默认。
    写操作一直等待 审批卡和当前权限模式 核对路径或命令后允许一次；必要时切换权限模式。
    回答中断或工具结果未知 /status、/requests 先检查工作区与外部副作用，再恢复或回退。
    Workflow 停在 unknown /workflow journal <run-id> 检查 side-effect step；不要直接重放。 
    /doctor
/status
/diagnostics
/requests <turn-id>
/security

    数据目录与边界

    ~/.clawsmith/
  config.json          Provider 配置
  update-state.json    已跳过的更新版本
  sessions.sqlite      会话、事件、审批、租约、任务和 Workflow
  memory/              长期记忆与归档
  skills/              Skill、候选与归档
  agents/              AGENTS.md 定义与启用状态
  snapshots/           文件检查点
  artifacts/           大工具输出
  commands/            后台任务日志和状态
  security/            认证与恢复审计
  diagnostics/         诊断包

    会话、记忆和 Skill 默认保存在本机；模型请求仍会发送到你配置的 Provider。工作区路径、 命令沙箱、Hook 和审批也无法被长期记忆或 Agent manifest 覆盖。
